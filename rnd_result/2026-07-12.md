## 2. 🔴 Wajib: Async Request APIs

### params — Page/Layout

✅ **Beberapa page udah migrasi** (`params: Promise<{ id: string }>` + `await params`):
- `product-component/cover-note/update/[id]/page.tsx`
- `product-component/placing-slip/update/[id]/page.tsx`

❌ **Perlu dicek ulang** — sisanya. Berdasarkan scan, tidak ada page yang destructure `{ params }` langsung tanpa type. Tapi **pastikan semua pages** yang punya `[param]` di path-nya udah pake `async` + `await params`.

**Contoh perubahan:**
```tsx
// ❌ Next.js 15
export default function Page({ params }: { params: { id: string } }) {
  return <div>{params.id}</div>
}

// ✅ Next.js 16
export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  return <div>{id}</div>
}
```

### headers() — fetchServerApi.ts

📁 **`src/libs/fetchServerApi.ts`** pake `import { headers } from 'next/headers'` — **perlu async**.

Udah pake `await headers()` di interceptor, tapi tetap perlu verifikasi bahwa pemanggilan `headers()` selalu di-await.

### cookies() — middleware.ts

📁 **`src/middleware.ts`** pake `request.cookies` (dari `NextRequest`) — ✅ **Ini aman**, karena `NextRequest.cookies` adalah property sync. Hanya `cookies()` dari `next/headers` yang affected.

### searchParams — Pages

✅ **Tidak ada yang pake `searchParams` di page props.** Semua `searchParams` dipake via `URL.searchParams.get()` di route handlers (API), yang tetap sync.

## 3. 🟡 Turbopack Default

### Status

- **Dev:** Udah pake `next dev --turbo` ✅
- **Build:** `next build` (no flag) — di Next.js 16 otomatis pake Turbopack
- **Custom webpack:** ❌ Tidak ada custom webpack di `next.config.js` ✅ **Aman**

### Yang perlu dicek

| Item | Status |
|------|--------|
| `transpilePackages` (chart.js, react-chartjs-2, exceljs, dll) | ✅ Didukung Turbopack |
| `optimizePackageImports` (experimental) | ✅ Didukung Turbopack |
| `terser-webpack-plugin` di devDeps | 🟡 Cuma sebagai fallback, gak aktif |
| Sass imports | ✅ Cuma 2 file, no tilde |

**Action:** Hapus flag `--turbo` dari script `dev` dan `build`, karena Turbopack jadi default.

## 4. 🟡 Middleware → Proxy

📁 **`src/middleware.ts`** — middleware kompleks dengan:
- JWT decode/encode
- Refresh token Keycloak
- Chunked cookies (token > 4KB)
- Redirect logic

Di Next.js 16:
- `middleware.ts` → **`proxy.ts`** (rename)
- `export async function middleware` → **`export default function proxy`**
- Masih bisa jalan sebagai deprecated, tapi disarankan migrasi

---

## 5. 🟡 `next lint` Removal

Di Next.js 16, `next lint` dihapus. ASUM saat ini pake:
- `"lint": "next lint"` di package.json
- `"lint:strict": "eslint --max-warnings=0 src"` — ini udah ESLint langsung ✅

**Action:** Ganti script `lint` jadi `eslint src` langsung. Hapus `eslint: { ignoreDuringBuilds: true }` dari next.config (gak relevan lagi).

## 7. 🟢 Minor Changes

### next/image — query string
Jika ada local image src pake query string, perlu `images.localPatterns` config. **Action:** scan dulu.

### Node.js version
Min 20.9+. Saat ini `"node": ">=20.3.0"` — **perlu update ke `>=20.9.0`**.

### ESLint extends
Pake `"next"` dan `"next/core-web-vitals"` di `.eslintrc` — di Next.js 16 masih supported tapi best practice pake `@next/eslint-plugin-next` langsung.

## 9. 🔍 Rekomendasi

### Strategi Migrasi

```
Branch: chore/nextjs-16-migration
Base: development
```

**Step-by-step:**

1. **Buat branch migrasi** — `chore/nextjs-16-migration` dari `development`
2. **Upgrade packages:**
   ```bash
   npm install next@latest react@latest react-dom@latest
   npx @next/codemod@canary upgrade latest
   ```
3. **Fix async params di semua pages/layouts/route handlers**
4. **Middleware → proxy** (rename + adjust export)
5. **Update package.json scripts**
   - `lint`: `next lint` → `eslint src`
   - `dev`: hapus `--turbo`
6. **Update node engine** → `>=20.9.0`
7. **Test:**
   - `npm run dev` — cek fast refresh
   - `npm run build` — cek Turbopack build
   - `npm run lint:strict`
   - `npm run typecheck`
   - `npm test` (jest)
8. **Enable React Compiler** di branch terpisah setelah migrasi landing

### ⚠️ Risiko

| Risiko | Mitigasi |
|--------|----------|
| Build gagal karena Turbopack incompatibility | Fallback: `next build --webpack` |
| Middleware broken setelah rename | Test auth flow thoroughly |
| Page params tidak await | Codemod seharusnya handle, tapi perlu review manual |
| next-auth compatibility | Test login flow + refresh token |

### 🎯 Timeline Estimate

| Step | Estimate |
|------|----------|
| Codemod + package upgrade | 30 menit |
| Manual fix (params, middleware, scripts) | 2-3 jam |
| Testing (dev, build, lint, TS, test) | 1-2 jam |
| **Total** | **~4-5 jam** |

## 10. 📌 Kesimpulan

**ASUM bisa migrasi ke Next.js 16.** Breaking changes-nya manageable karena:

✅ Udah pake Turbopack di dev (75% jalan)
✅ Gak ada custom webpack
✅ Gak ada sync `cookies()/headers()` berbahaya (cuma 1 file `fetchServerApi.ts`)
✅ TypeScript & Node.js version udah ready
✅ Codemod resmi dari Next.js untuk automigrasi

**Rekomendasi:**
1. Jangan campur migrasi + React Compiler — dua branch terpisah
2. Bikin **`chore/nextjs-16-migration`** dulu
3. Stabilkan → baru **enable React Compiler** di branch terpisah
4. Kalo waktu terbatas, **stay di 15.5.9 dulu** — masih didukung dan mature
