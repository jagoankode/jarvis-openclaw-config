## 🧪 ASUM: CaseTransfer Refactor (IIAU-344)

### Status 07:47 WIB
**Undone battle ⚔️ — ESLint vs Prettier infinite loop**

### What happened
- Bos minta fix ESLint di `CaseTransfer/` module (component + hooks)
- ASUM pake Prettier — setiap autofix ESLint, prettier reformat → baris berubah → kena `max-lines-per-function: 35` lagi
- Infinite loop: ESLint fix → prettier → ESLint → prettier → ...

### Key constraints causing loop
1. Prettier breaks compact code jadi multi-line (nambah baris)
2. `max-lines-per-function: 35` strict — hampir gak feasible untuk hook dengan complex state + callbacks
3. `jsdoc/require-jsdoc` + `explicit-function-return-type` di arrow function — kena juga di return object methods
4. `jsdoc/require-param` dan `no-object-jsdoc-type` (`@param {object}`)
5. User said "haram" pakai `eslint-disable` — harus solve properly

### What was tried
1. **Compact variables** — prettier break jadi multi-line, jadi gak membantu
2. **Split jadi 3 hooks** (`useInitTransferMutations`, `useInitTransferState`, `useTransfer`) — masih > 35 per prettier
3. **Module-level functions** (`_execReopenAction`, `_execReassignAction`, etc.) — JSDoc jadi masalah
4. **Explicit return types + proper JSDoc** — tapi prettier break multi-line return jadi > 35
5. All file rewrite with complete JSDoc → autofix nambahin JSDoc kosong → infinite

### Where it left off
- **TSC ✅** (0 errors)
- **ESLint:** 50+ JSDoc errors (autofix nambahin JSDoc kosong → dianggap incomplete)
- Component ✅ bersih (0 errors)
- Hooks: semua JSDoc ke module-level functions missing
- WSL connection masih via tunnel localhost:43210

### Lesson learned
- `eslint-disable` di `max-lines-per-function` for hooks is pragmatic, but user rejects it
- Prettier + strict ESLint mixed rules create an infinite loop that's hard to break
- Sub-agent atau task dedikasi bisa jadi solusi daripada main thread

### Next steps plan
1. **Approach final**: Baca file hooks saat ini → generate JSDoc lengkap semua module-level functions (10-15 functions) sekaligus dalam 1 rewrite
2. Kalo masih error → approach alternatif: merge semua hooks jadi 1 hook besar + extract return builder jadi function di luar hook
3. Kalo masih loop → bicara sama Bos untuk relax aturan sementara

## 📏 Hard Rules (dari Brillian, WAJIB diingat)

### ❌ DILARANG KERAS
1. **`eslint-disable`** — semua bentuk (`eslint-disable`, `eslint-disable-next-line`, `eslint-disable-line`) — HARAM
2. **`@param {Type | undefined} name`** — JSDoc format WRONG → harus `@param {Type} [name]`
3. **`param: Type | undefined`** — di function signature → harus `param?: Type`
4. **`any`** — dilarang (kecuali benar2 terpaksa, itupun harus ada persetujuan)
5. **Comments di `.type.ts` file** — tidak diperlukan sama sekali (baik field-level maupun top-level)
6. **Variable/parameter abbreviations** — `wf`, `ids`, `ts`, `q`, `srch`, `reopenMt`, `reassignMt`, `azAuth`, `ul`, `aa`, `st`, `mut`, `ca`, `fn`, `p`, `s`, `r`, `tld`, `usr`, `dt`, `val`

### ✅ WAJIB
1. **Optional param** → harus di akhir parameter list
2. **JSDoc optional** → `@param {Type} [name]` bukan `@param {Type | undefined} name`
3. **TypeScript optional** → `param?: Type` bukan `param: Type | undefined`
4. **Variable naming** → deskriptif, camelCase, English
5. **Type declarations** → ONLY in `.type.ts` / `.types.ts` files

## 🔧 ESLint Config (Applied)
- Override 1: `**/*.{component,container,wrapper,config,hook,hooks,test}.{ts,tsx}` → bans TSTypeAliasDeclaration/TSInterfaceDeclaration
- Override 2: `case-management-revamp/**/*.{ts,tsx}` + `excludedFiles: ["**/*.type.ts", "**/*.types.ts"]` → bans type declarations for non-type files
- Type declarations allowed freely in `.type.ts`/`.types.ts`

## 📌 Convention Rules (from code-convention.md)
- Module Architecture (component/container/hook split)
- JSDoc mandatory on public funcs
- No `useState`/`useEffect` in `.component.tsx`
- Event Handler: `onClick={handle}` not `onClick={() => handle()}`
- Private funcs: `_` prefix
- Constants: `UPPER_SNAKE_CASE`
- Boolean vars: `is`, `has`, `can`, `should` prefix
- Arrays: plural form
- Test naming: `should + expected behavior`

- No `useState`/`useEffect` in `.component.tsx`
- Event Handler: `onClick={handle}` not `onClick={() => handle()}`
- Private funcs: `_` prefix
- Constants: `UPPER_SNAKE_CASE`
- Boolean vars: `is`, `has`, `can`, `should` prefix
- Arrays: plural form
- Test naming: `should + expected behavior`
