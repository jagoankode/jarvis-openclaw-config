**XML (Legacy / Standard Lama)**
- Layout ditulis di `.xml`, logic di `.kt`/`.java`
- **Declarative?** Enggak. Lo bikin hierarki View di XML, trus reference pake `findViewById()` atau `ViewBinding`
- **State management:** Manual. Kalo data berubah, lo harus navigasi ke View trus update manual (`textView.text = ...`)
- **Preview:** Layout Editor (kadang lemot)
- **Reusability:** Pake `<include>` atau custom View (ribet)
- **Learning curve:** Rendah — familiar buat yang udah main Java/XML
- **Performance:** Lebih ringan di render pertama, tapi lebih berat pas update dinamis
- **Tooling mature:** Linter, constraint layout, dll udah stabil

**Jetpack Compose (Modern UI Toolkit)**
- Layout ditulis di **Kotlin** langsung — **declarative**: lo bilang "ini gimana munculnya", bukan "gimana caranya"
- **State-driven:** `val text by remember { mutableStateOf("...") }` — data berubah → UI **auto recompose**. Gak perlu manual update
- **Preview:** `@Preview` annotation — bisa preview fungsi Composable dari IDE
- **Reusability:** Bikin custom Composable function — sesimpel manggil function biasa
- **Learning curve:** Perlu paham Kotlin lumayan + reactive state (Coroutines/Flow bantu)
- **Performance:** Agak berat di render pertama (Compose runtime), tapi recomposition cerdas — cuma bagian yg berubah yg di-render ulang
- **Modern features:** Animation, theming, dark mode, Material3 — built-in dan gampang
- **Interop:** Bisa pake XML di dalam Compose pake `AndroidView`, atau Compose di dalem XML pake `ComposeView`

assistant: **Struktur Project — XML vs Jetpack Compose**

**📁 XML (Tradisional)**
```
app/
├── src/main/
│   ├── java/com/example/app/
│   │   ├── MainActivity.kt
│   │   ├── adapter/
│   │   │   └── UserAdapter.kt          # RecyclerView adapter
│   │   ├── fragment/
│   │   │   └── HomeFragment.kt
│   │   └── viewmodel/
│   │       └── HomeViewModel.kt
│   ├── res/
│   │   ├── layout/
│   │   │   ├── activity_main.xml       # Layout utama
│   │   │   ├── fragment_home.xml
│   │   │   └── item_user.xml           # List item layout
│   │   ├── drawable/
│   │   │   └── bg_card.xml             # Shape/gradient (XML)
│   │   ├── values/
│   │   │   ├── strings.xml
│   │   │   ├── colors.xml
│   │   │   └── themes.xml
│   │   └── menu/
│   │       └── nav_menu.xml
```

**Ciri-ciri:**
- **Split file:** Setiap halaman punya 2 file (XML layout + Kotlin/Java Fragment)
- **res/layout/** — semua layout UI di sini
- **res/drawable/** — banyak file XML untuk shape, selector, gradient
- **res/values/** — warna, string, tema
- **Adapter + ViewHolder** — harus bikin kelas terpisah buat list/recycler

---

**📁 Jetpack Compose (Modern)**
```
app/
├── src/main/
│   ├── java/com/example/app/
│   │   ├── MainActivity.kt
│   │   ├── ui/
│   │   │   ├── theme/
│   │   │   │   ├── Theme.kt           # Material3 theme
│   │   │   │   ├── Color.kt           # Warna langsung Kotlin
│   │   │   │   └── Type.kt            # Typography
│   │   │   ├── screens/
│   │   │   │   ├── HomeScreen.kt      # Home page (UI + logika ringan)
│   │   │   │   └── ProfileScreen.kt
│   │   │   └── components/
│   │   │       ├── UserCard.kt        # Composable reusable
│   │   │       └── BottomNav.kt
│   │   ├── navigation/
│   │   │   └── NavGraph.kt            # NavHost → routes
│   │   └── viewmodel/
│   │       └── HomeViewModel.kt
│   └── res/
│       └── values/
│           └── strings.xml            # (Opsional, bisa pake string literals)
```

**Ciri-ciri:**
- **res/layout/** —  **HILANG total.** Semua layout di file Kotlin
- **res/drawable/** — minimal. Vektor cukup `.xml` vector drawable, sisanya Kotlin
- **res/values/strings.xml** — masih dipake buat localization, tapi banyak yg pake constant di Kotlin
- **ui/theme/** — semua theme info di Kotlin (warna, font, shape — bukan XML)
- **TANPA adapter** — bikin list? Tinggal `LazyColumn { items(data) { UserCard(it) } }`

assistant: **Anotasi di Jetpack Compose — yang lo bakal temui tiap hari:**

---

**1. `@Composable` — Yang Paling Inti**
```kotlin
@Composable
fun Greeting(name: String) {
    Text(text = "Halo $name")
}
```
- Tanda bahwa fungsi ini **bisa nge-render UI**
- Cuma fungsi pake `@Composable` yang bisa manggil fungsi `@Composable` lain
- **Bukan annotation biasa** — ini compiler plugin, beda level

---

**2. `@Preview` — Buat Liat UI Tanpa Build**
```kotlin
@Preview(showBackground = true, showSystemUi = true)
@Composable
fun GreetingPreview() {
    Greeting(name = "Bos")
}
```
- Muncul di IDE panel **Design / Split view**
- Bisa dikasih parameter:
  - `showBackground = true` — background putih
  - `showSystemUi = true` — liat status bar
  - `widthDp`, `heightDp` — ukuran preview
  - `locale`, `uiMode` — simulasi lokal/dark mode
- **Bisa banyak** — taro beberapa `@Preview` di fungsi berbeda

---

**3. `@Immutable` & `@Stable` — Optimasi Recomposition**
```kotlin
@Immutable
data class User(val name: String, val age: Int)
```
- Ngasih tau Compose: "class ini gak bakal berubah tanpa dibikin ulang"
- Compose jadi **gak perlu ngecek ulang** → performa lebih kenceng
- `@Immutable` — semua properti final, gak pernah berubah
- `@Stable` — properti bisa berubah, tapi Compose tau kapan berubahnya
- Wajib dipasang di **data class / sealed class** yang dipake state

---

**4. `@OptIn` — Akses API Experimental / Internal**
```kotlin
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun MyScreen() {
    // pake API Material3 yang masih experimental
    TopAppBar(title = { Text("...") })
}
```
- Kadang Google ngerilis fitur baru dengan label experimental
- Lo harus "opt-in" secara eksplisit biar bisa pake
- Alternatif: kasih di file level `@file:OptIn(...)` biar gak tiap fungsi

---

**5. `@ExperimentalComposeApi` — API Blom Stabil**
```kotlin
@ExperimentalComposeApi
@Composable
fun ExperimentalFeature() { ... }
```
- Buat fungsi yang lo bikin sendiri yang **belum stabil**
- Ngasih warning ke developer lain: "ini masih eksperimen, gue bisa ubah kapan aja"

---

**6. `@StableMarker` — Flag Buat Anotasi Lain**
```kotlin
@StableMarker
annotation class Stable
```
- Dipake sama Google buat bikin `@Stable` dan `@Immutable`
- Lo gak bakal langsung pake ini — cuma compiler yang butuh

---

**📊 Yang Paling Sering Dipake:**

| Anotasi | Frekuensi | Wajib? |
|---------|-----------|--------|
| `@Composable` | 🔴 **Setiap fungsi UI** | ✅ Wajib |
| `@Preview` | 🟡 Sering pas develop | ⬜ Opsional |
| `@OptIn` | 🟡 Sesekali | ⬜ Kalo pake API experimental |
| `@Immutable` / `@Stable` | 🟢 Kadang2 | ⬜ Best practice buat performa |
| `@ExperimentalComposeApi` | 🟢 Jarang | ⬜ Kalo bikin library |

---

**Catatan:** `@Override`, `@Nullable` dll masih dipake di Android biasa. Tapi di Compose, anotasi Java standard itu gak relevan — lo pake **Kotlin keyword** instead (`override`, `?` buat nullable).

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun MyScreen() {
    // pake API Material3 yang masih experimental
    TopAppBar(title = { Text("...") })
}
```
- Kadang Google ngerilis fitur baru dengan label experimental
- Lo harus "opt-in" secara eksplisit biar bisa pake
- Alternatif: kasih di file level `@file:OptIn(...)` biar gak tiap fungsi

---

**5. `@ExperimentalComposeApi` — API Blom Stabil**
```kotlin
@ExperimentalComposeApi
@Composable
fun ExperimentalFeature() { ... }
```
- Buat fungsi yang lo bikin sendiri yang **belum stabil**
- Ngasih warning ke developer lain: "ini masih eksperimen, gue bisa ubah kapan aja"

---

**6. `@StableMarker` — Flag Buat Anotasi Lain**
```kotlin
@StableMarker
annotation class Stable
```
- Dipake sama Google buat bikin `@Stable` dan `@Immutable`
- Lo gak bakal langsung pake ini — cuma compiler yang butuh

---

**📊 Yang Paling Sering Dipake:**

| Anotasi | Frekuensi | Wajib? |
|---------|-----------|--------|
| `@Composable` | 🔴 **Setiap fungsi UI** | ✅ Wajib |
| `@Preview` | 🟡 Sering pas develop | ⬜ Opsional |
| `@OptIn` | 🟡 Sesekali | ⬜ Kalo pake API experimental |
| `@Immutable` / `@Stable` | 🟢 Kadang2 | ⬜ Best practice buat performa |
| `@ExperimentalComposeApi` | 🟢 Jarang | ⬜ Kalo bikin library |

---

**Catatan:** `@Override`, `@Nullable` dll masih dipake di Android biasa. Tapi di Compose, anotasi Java standard itu gak relevan — lo pake **Kotlin keyword** instead (`override`, `?` buat nullable).

Ada yang mau dijelasin lebih dalem, misal beda `@Immutable` vs `@Stable` atau contoh implementasinya? 🧪
